# Dot Desktop Agent

Objective: turn Click Dot into an always-running desktop agent with its own chat that can see the user's screen (with permission), be called on demand, and be installed, updated and removed by click-ai-devkit.
Branches: `click-dot` tracker `feat/local-alpha` (feature-branch-chain); `click-ai-devkit` new feature branch for the installer task. Delivery strategy: ask-on-risk. Test runners: `npm test` (click-dot), `go test ./...` (click-ai-devkit).

## Specs

- S1 — Installed with the devkit. User: "Que cuando instalemos el click ai dev kit, instalemos esto que traemos que es el repositorio que altera claude, y esas cosas, que traemos pero tambien click dot" and "quiero que se instale todo con el click ai dev kit". `click install`/`update`/`uninstall`/`doctor` manage Dot like the rest of Click-managed content.
- S2 — Always running and callable. User: "click dot quiero que viva y vea todo, puedas llamarlo, etc".
- S3 — Own chat, sees what the user does with permission. User: "quiero que sea como un pequeño agentito que tiene su propio chat, que ve todo lo que haces, si se lo permites, etc". Reference: https://www.copilotkit.ai/blog/introducing-opendots
- S4 — Screen observation from the first version, not only developer-tool activity. User: "dale necesito que desde el inicio".
- S5 — The model receives the screen images, not only locally extracted text. User: "que vea".
- S6 — Before an image leaves the machine, Dot blurs regions containing personal data, found locally with OCR and the memory-guard patterns; the model still sees the screen. User answered "si" to: "propongo que Dot difumine en la máquina las zonas con datos personales antes de enviar cada imagen. Usaría OCR para encontrar el texto y los patrones del `memory-guard` para decidir qué difuminar. El modelo sigue viendo la pantalla, pero no los nombres, documentos o pólizas. ¿Incluimos ese difuminado en la tarea 3?"
- S7 — Simple, non-invasive companion instead of an app window. User: "click dot se hizo app, pero tiene que ser menos invasivo, mas simple, no una maldita app ahi, donde esta la simplicidad? deberia de salir una mascotita, con botones \"compartir mi pantalla, voz, mensaje\" para trabajar con el, entiendes?"
- S8 — Sign-in must work in the installed app. User: "ni se conecta con chat gpt [...] y de ahi no pasa, esta bloqueado el boton de iniciar sesion con chat gpt" (fixed in `7de5e57`).
- S9 — Voice input through Windows' built-in speech recognition. User answered "si" to "¿Voy con el de Windows?" after: "Mi recomendación es usar el reconocimiento de voz que trae Windows: no agrega peso a Dot y funciona igual que el OCR que ya usamos."

Assumptions (not user requirements; confirm or correct):
- A1 — Windows first, since the devkit is distributed through Scoop. macOS/Linux later.
- A2 — Desktop shell is Electron: it can host the existing Next.js/Node server and provides screen capture, tray, autostart and global shortcuts natively. Tauri would need a Node sidecar for the existing code.
- A3 — Model access keeps the existing per-user Sign in with ChatGPT flow; image input through `POST /v1/responses` must be verified before T3.
- A4 — "si se lo permites": capture is off until the user turns it on, shows a visible indicator while active, and can be paused at any time.
- A5 — T2 capture design: when the user turns capture on, Dot captures the primary display every 10 seconds into an in-memory ring buffer of the last 6 frames (about one minute). Frames are never written to disk and are dropped on pause, quit or capture off. The on/off choice persists across restarts. While capturing, the tray icon and tooltip show it, and the chat window shows a visible "Dot can see your screen" indicator with Pause. Capture runs in the Electron main process (`desktopCapturer`), so web permissions stay denied.
- A6 — T3 design: while capture is on, each chat message includes the latest frame by default, after local redaction; the composer shows the redacted preview and the number of hidden regions, with a control to leave the screen out of that message. Nothing is sent when OCR, pattern loading or redaction fails (fail closed); the UI says why. OCR uses Windows.Media.Ocr through a Windows PowerShell 5.1 helper fed over stdin (no temp files); redaction is solid pixelation of padded word boxes; patterns are vendored from click-ai-devkit `internal/guard/patterns.yaml` as generated JSON checked by a shared golden corpus. OCR can miss text and faces/photos are not covered.
- A7 — Mascot design (S7): no main window. A small frameless, transparent, always-on-top, skip-taskbar window shows the Click "spark" as the mascot in a screen corner (default bottom-right of the work area), draggable, position remembered. Clicking it toggles three buttons with the user's labels "Compartir mi pantalla", "Voz" and "Mensaje" (Spanish, as the user named them). "Compartir mi pantalla" toggles capture with the visible indicator; "Mensaje" opens a compact chat bubble beside the mascot (sign-in prompt there when not connected; sign-in still finishes in the system browser); "Voz" listens and puts the transcript in the message box for review before sending. The tray keeps Quit and Start with Windows; `Ctrl+Shift+Space` toggles the bubble.
- A8 — Voice (S9): Windows PowerShell 5.1 helper using Windows speech recognition (System.Speech or Windows.Media.SpeechRecognition, whichever works unpackaged and supports es/en), started on demand, stops on silence or a second click, returns text only; audio is never stored or sent; the microphone is used by the helper, so web permissions stay denied. Missing recognizer/language or microphone fails with a clear message.

Known constraint: current storage fails closed on native Windows until private ACLs can be verified (README). T1 must solve protected storage on Windows.

Open risk: S5 sends screenshots that may contain insured-party personal data to OpenAI under each user's personal ChatGPT account. S6 reduces it; Click Seguros legal/compliance approval is still pending before team rollout.
